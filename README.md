# Ozon Product Parser

Парсер сохраняет результат в CSV и поддерживает повторный запуск без повторной обработки уже сохранённых товаров. Дополнительно добавлен Airflow DAG для ежедневного запуска парсера.

## Что реализовано

- получение и сохранение cookies после авторизации в Ozon;
- загрузка cookies в браузер и проверка авторизации;
- парсинг списка SKU из файла;
- сбор основных данных о товаре:
  - SKU;
  - название;
  - цена;
  - рейтинг и количество отзывов;
  - обложка;
  - количество фото и видео;
  - цвет;
  - материал;
  - комплектация;
  - наличие rich content;
- сохранение результатов в CSV;
- сохранение необработанных SKU в отдельный файл (чаще всего это товары, которых нет в наличии);
- продолжение работы с уже существующим CSV;
- работа в Windows и Linux/WSL;
- ежедневный запуск через Airflow.

## Особенность авторизации

Изначально предполагалось автоматическое получение одноразового кода через Gmail API.

На момент выполнения задания текущий сценарий авторизации Ozon требует подтверждения входа кодом с телефона и не дает
возможность пройти авторизацию только с использованием почты, поэтому в таком виде задание технически нереализуемо.
Я остановился на таком варианте получения cookies:

1. `get_cookies.py` открывает страницу входа Ozon.
2. Пользователь вручную вводит номер телефона и код подтверждения.
3. Скрипт проверяет, что авторизация завершена.
4. Cookies сохраняются в `cookies.json`.
5. `parse_ozon.py` использует эти cookies при последующих запусках.

Если cookies истекли, достаточно повторно запустить `get_cookies.py`.

## Запуск
Скрипты работают как с ОС Windows, так и с ОС Linux.

Важно: для успешной авторизации и получения `cookies.json` запуск скрипта `get_cookies.py` необходимо выполнять в
системе с графическим интерфейсом. Если парсер запускается на Linux-сервере без GUI, cookies.json можно 
предварительно получить на Windows/Linux с графическим интерфейсом и затем скопировать в директорию проекта.

### 1. Установить зависимости

Пример для виртуального окружения:

Linux / WSL:
```bash
python3 -m venv .venv
source .venv/bin/activate

pip install -r requirements.txt
```

Windows PowerShell:
```bash
python -m venv .venv
.\.venv\Scripts\Activate.ps1

pip install -r requirements.txt
```

На Linux без GUI также должны быть установлены Google Chrome, Xvfb и xauth.

### 2. Настроить `.env`

Linux / WSL:
```bash
cp .env.example .env
```

Windows PowerShell:
```bash
Copy-Item .env.example .env
```
Пример:

```dotenv
SKU_FILE=sku_list.txt
RESULTS_FILE=results.csv
CHECK_AUTH=true
PAUSE_SECONDS=1
PAUSE_JITTER_SECONDS=0.7
USE_XVFB=false
```
Описание переменных:

`SKU_FILE` — имя файла со списком SKU для обработки. Он должен содержать список SKU, разделённых переносами строк, пробелами или запятыми.

`RESULTS_FILE` — имя CSV-файла, в который будут сохраняться результаты.

`CHECK_AUTH` — проверять ли авторизацию после загрузки сохранённых cookies (true / false).

`PAUSE_SECONDS` — базовая пауза между обработкой товаров, в секундах.

`PAUSE_JITTER_SECONDS` — случайное отклонение от базовой паузы. Например, при `PAUSE_SECONDS`=1 и `PAUSE_JITTER_SECONDS`=0.7 задержка будет случайной примерно в диапазоне от 0.3 до 1.7 секунды.

`USE_XVFB` — запускать ли виртуальный дисплей Xvfb. Для Windows и Linux с GUI обычно используется false, для Linux без графического окружения — true.


### 3. Получить cookies

```bash
python get_cookies.py
```

В открывшемся Chrome нужно вручную пройти авторизацию. После успешного входа будет создан `cookies.json`.

### 4. Запустить парсер

```bash
python parse_ozon.py
```

Результат будет сохранён в файл, указанный в `RESULTS_FILE`. Если часть товаров не удалось обработать, рядом будет создан
файл с именем `имя результата_failed.txt`


## Airflow

Airflow является дополнительной частью проекта и устанавливается в отдельное виртуальное окружение. 
DAG рассчитан на Airflow 3.x с установленным apache-airflow-providers-standard

В репозитории есть `ozon_parser_daily.py` — простой DAG для ежедневного запуска парсера.

Перед запуском Airflow необходимо указать путь к директории проекта:

```bash
export OZON_PROJECT_DIR=/home/user/ozon-parser
```

В этой директории должны находиться `parse_ozon.py`, `.env`, `cookies.json` и виртуальное окружение `.venv`.
Имя выходного CSV задаётся в `.env` через переменную `RESULTS_FILE`.
DAG помещается в папку Airflow `dags/`. После запуска Airflow он появляется в UI как `ozon_parser_daily`.



## Тестирование

Проект проверялся на Windows и Linux/WSL. 

Помимо небольших тестов на 20-30 SKU я решил провести достаточно масштабный тест
на парсинг 1000 SKU. Для этого сначала я создал отдельный скрипт, который в рамках определенных категорий товаров собрал
1000 валидных SKU с Ozon. Затем я провел два эксперимента: 
- При запуске парсера на 1000 SKU **без использования cookies** приблизительно 170 товаров были корректно обработаны, после этого
в браузере появился пазл и Ozon стал отвечать HTTP 403
- Далее я повторил эксперимент, но уже **с использованием cookies**. Результат - 994 товара были корректно обработаны и данные 
по ним были записаны в CSV таблицу, остальные 6 товаров не были обработаны, потому что их не было в 
наличии в момент проведения теста.


На Linux/WSL проверена работа браузера через Xvfb и повторная обработка временно неудачных SKU. Airflow DAG успешно 
запускал парсер вручную и по расписанию.

Ошибки отдельных товаров не приводят к потере уже собранного результата: каждая успешная строка сразу записывается в CSV.
